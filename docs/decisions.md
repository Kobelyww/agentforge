# 设计决策记录 (ADR)

每个决策回答三件事：当时的选择、为什么、放弃了什么。按面试常问深度排序。

## ADR-1: 自研 Agent 运行时，而不是基于 LangChain/LlamaIndex

**选择**：ReAct 循环、流式事件、工具注册表全部自研（依赖里没有任何 Agent 框架）。

**为什么**：
- 行业 Agent 的可靠性问题大多出在框架黑盒：循环次数、上下文拼装、工具失败
  语义都不可控。自研后每一行逻辑都可解释、可测、可改。
- 事件模型（`AgentEvent`）是我们与 UI/评测的契约。框架的事件粒度做不到
  "计划→步骤→工具"三级trace 的干净投影。
- 面试视角：会用框架证明你能干活，能讲清楚框架帮你隐藏了什么证明你能扛事。

**代价**：放弃了现成的记忆管理、丰富集成。用 MCP 弥补集成面，用自研
`SessionMemory`（滚动摘要）覆盖核心记忆需求。

## ADR-2: Plan-and-Execute 与 ReAct 并存，而非只留一个

**选择**：运行时同时支持两种编排，按请求选择。

**为什么**：ReAct 对单轮问答更省 token 也更快；规划模式对多步诊断任务可控性
显著更好（显式计划可审、步骤可并行化、断点可续）。行业场景里两者都真实存在，
强制二选一是伪命题。

**代价**：维护两条编排路径。通过抽出共享的 `_react` 内循环把增量成本压到
Planner/Synthesizer 两个 prompt 与少量胶水代码。

## ADR-3: MCP 集成是"兼容子集"而不是完整协议实现

**选择**：实现 stdio 传输 + `initialize / tools/list / tools/call` 核心方法集。

**为什么**：这三个方法覆盖了工具挂载的完整闭环（握手→发现→调用），是收益/
复杂度比最高的一段。完整的 MCP 规范还包括 resources/prompts/sampling 等，
对本场景是过度工程。协议帧用标准 newline-delimited JSON-RPC 2.0，因此示例
Server 可以被任何 MCP 客户端（Claude Desktop / Cursor）挂载，互通性没有被
削减。

**代价**：暂不支持 MCP resources/prompts。接口留了扩展位。

## ADR-4: SQLite 作为唯一持久层

**选择**：全量数据（会话/消息/文档/chunk/工具审计/工单）存 SQLite（WAL）。

**为什么**：
- "审计日志是事实，视图是投影" —— Trace、记忆、评测全部从同一张消息表重建，
  一个存储引擎保证了事务一致性。
- 零部署依赖是这个项目的核心体验承诺（clone → run），SQLite 是唯一满足
  "删掉 Docker 也能跑"的选项。
- 单机写路径全部经 `asyncio.to_thread` + 进程内锁，本地延迟亚毫秒，实测
  不是瓶颈（见 metrics）。

**代价**：不支持多实例水平扩展。迁移路径明确（SQLAlchemy 抽象层 → Postgres），
列入 Roadmap。

## ADR-5: 代码沙箱是进程级隔离，并诚实标注边界

**选择**：`python -I` 子进程 + RLIMIT + 墙钟超时 + 会话工作目录。

**为什么**：在演示与内网工具场景，这个强度已覆盖"意外死循环/内存爆炸/写穿
磁盘"三类真实事故；而容器/gVisor 池会让"clone 即用"变成"先装 Docker 配额"。

**明确不设防**：内核逃逸、网络外呼、侧信道。多租户生产环境的正确答案写在
架构文档里 —— 换执行后端（容器池/gVisor）只需实现同一个 `Tool` 接口，
接口即边界。

## ADR-6: 故障转移不允许在部分输出后切换 provider

**选择**：注册表级 failover 只在首个事件产出前生效。

**为什么**：流式输出一旦开始，换 provider 重放 = 消费端收到重复文本。重试
边界必须与"用户看到的东西"一致：没看到的东西可以换引擎重来，看到了的东西
只能如实报错。

**代价**：首 token 后的失败只能向上传播。配套缓解：适配器内部对"未产出"
的连接错误先做重试，把大部分瞬时故障消化在 failover 之前。

## ADR-7: Hashing Embedding 作为离线兜底，而不是要求外部向量服务

**选择**：本地 md5 特征哈希嵌入（确定性）+ BM25，RRF 融合；有 API Key 时
自动升级 Provider 嵌入。

**为什么**：行业 demo 的第一体验是"五分钟内看到完整闭环"，任何"先去申请
向量库"都是流失点。特征哈希嵌入质量低于训练模型，但 BM25 补齐精确词匹配
后，领域词表场景的召回足够可演示；且 md5 哈希跨进程确定性使向量可持久化
复现（Python 内建 `hash()` 是加盐的，这是个真实的坑）。

**代价**：语义泛化弱。换用 Provider 嵌入无需改任何检索代码（接口一致）。

## ADR-8: 评测集是代码的一部分，不是文档的一部分

**选择**：`examples/suites/forgeops.yaml` 断言工具编排序列 + 结论内容，
`agentforge eval` 退出码参与 CI 门禁。

**为什么**：Agent 项目最贵的回归是"改了 prompt，工具编排悄悄变了"。把
评测写进 CI 后，每次变更的语义影响在合并前可见。断言分两层：编排层
（工具序列）对 prompt 变化敏感，内容层（结论关键字）对模型退化敏感。

**代价**：Mock Provider 上的评测验证的是编排逻辑而非模型智能；真实模型的
评测需要同一套 harness 换 provider 跑（已支持 `--model` 参数）。
